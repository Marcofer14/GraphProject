# v0.5.0 · Anytime search, 60-epoch model and the live demo

Attach `checkpoints/cvrp100_pomo_real_long.pt` as the release asset.

Live demo: https://marcofer14.github.io/GraphProject/

| Model | Trained | 200 unseen real routes |
|---|---|---|
| `cvrp100_pomo_real_long.pt` | `cvrp100_pomo_real` continued from epoch 40 to 60 on real route slices (ADR-017) | first answer **2.74 %** above the best in 0.57 s; network alone 9.69 % |

**Anytime search (ADR-021).** `attention_ils` keeps improving the first answer with iterated
local search until its time budget runs out. At equal computing time, all runs made without other
load on the machine:

| Budget | Our model + search | PyVRP | Ours better on | OR-Tools |
|---|---|---|---|---|
| 1 s | **1.19 %** | 1.60 % | 122 of 200 routes | 9.17 % |
| 2 s | **0.77 %** | 1.28 % | 128 of 200 routes | 8.09 % |

PyVRP given 10 s: 0.70 %. Driving time against the real drivers: **−10.5 %** (3.28 h → 2.94 h per
route from the first answer), shorter on all 200 routes.

**Whole station-days (ADR-020)**, now on 20 days no model saw: **11.88 fleet hours per day vs
13.18 for the drivers (−9.9 %)**, fewer on all 20 days, PyVRP 60 s 12.45 h (better on 10 of 20
days). This replaces the −12.5 % of v0.4.0, which came from 6 training-split days.

**Web demo (phase 6).** Static React + MapLibre page on GitHub Pages: compare any two plans on
25 random real routes with a shift replay, race the solvers against computing time (GPU or CPU),
re-plan whole station-days, and read how it works and its limits. Data are exported once with
`nr-demo-export`; the page computes nothing.

Other changes: `train.continue_from` (continue another run under a new name), `nr-bench
--min-routes`, the page revalidates its data after each deploy.

```bash
uv run nr-bench --mode route --split evaluation --n 200 \
    --configs reference pyvrp:1 attention_ils@checkpoints/cvrp100_pomo_real_long.pt:1
```
